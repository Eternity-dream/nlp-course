# 验收设计

以下验收案例依据[产品需求 R01–R24](requirements.md)设计，旅行预算口径、编辑规则、简化方案和搜索回退方向均已确认。西安为主要验证样本，另检查用户切换目的地；首个安装验收目标为 Windows（Intel／AMD），生成耗时与 API 调用费用不设目标。

## 固定案例

使用明确的日期、西安地点与资料快照，使每个案例都能判断具体行为。可自动判定的条件用规则检查，来源是否支持事实及行程是否值得采用结合人工复核。

| 编号 | 输入或场景 | 预期行为 | 对应规则 |
| --- | --- | --- | --- |
| A01 | 城市、日期、人数齐全，存在可靠地点与营业信息。 | 输出指定天数的早中晚安排、餐饮、交通和大致耗时。 | R13、R14 |
| A02 | 长期偏好为高强度游览，本次明确要求慢节奏。 | 本次行程遵循慢节奏，原偏好档案保留；页面不展示偏好匹配理由。 | R01、R04 |
| A03 | 两名同行者设置全程旅行预算，资料同时包含每人票价与一车费用。 | 门票按人数计算，共享车费计入一次，汇总全程门票、餐饮及当地交通；费用缺失时标记待确认，超预算时调整或提示冲突。 | R02、R12 |
| A04 | 只有目的地，没有旅行日期。 | 先追问日期；不生成假定日期的正式行程。 | R05 |
| A05 | 缺少一个不会显著改变结果的普通偏好。 | 展示采用的假设并继续生成。 | R05 |
| A06 | 两份资料只有一份与当前城市相关，偏好档案中存在明确限制。 | 使用相关资料与明确限制；不把资料中的描述自动提升为用户要求。 | R01、R06、R08 |
| A07 | 官方页面显示目标场馆在行程当日闭馆。 | 调整日期或替换活动；无法调整时指出冲突，不输出已通过核验的安排。 | R10、R12 |
| A08 | 相邻活动距离远，交通时间超过两个活动之间的可用时段。 | 检出冲突并调整或提示；估算交通耗时标为估算。 | R12 |
| A09 | 两个来源对同一日期的营业时间表述不一致。 | 保留来源与查询时间，展示冲突及待确认状态。 | R10、R11 |
| A10 | 搜索结果没有可靠票价或营业信息。 | 缺失事实标记待确认，生成的数字不替代来源。 | R11、R12 |
| A11 | 一个地点有多个同名门店，来源分别对应不同地址。 | 行程与依据指向同一具体门店，路线使用该门店的位置。 | R11、R12 |
| A12 | 用户增删活动、替换地点或调整顺序。 | 自动重排限于相关当天，其他日期保留；再次检查相关营业时间、相邻交通及全程预算。 | R12、R14、R21 |
| A13 | 用户本次删除一类活动，之后创建另一行程。 | 删除只影响本次安排；用户确认偏好更新后，后续规划才采用新偏好。 | R03 |
| A14 | 两份独立安装分别导入同名但内容不同的资料。 | 每份安装仅检索自身资料，生成请求和偏好更新均限于当前实例。 | R08、R15 |
| A15 | 用户查看、修改或删除偏好及资料。 | 页面体现操作结果；删除资料时清理活动库中的文件、正文片段和全文索引，后续检索与模型输入不再包含它。手动导出的备份由使用者管理。 | R03、R06、R08、R22 |
| A16 | 分别提供可提取文字的 PDF、扫描 PDF、文本、链接和收藏。 | 可读取内容能够导入并定位片段；扫描 PDF 提示提供文字版本，解析失败有明确反馈。 | R07 |
| A17 | 已选外部 AI 服务，发起一次带个人资料的规划。 | 检查实际请求只含必要片段；服务条款和配置符合训练用途及保留要求。 | R08、R09 |
| A18 | 规划提交成功后关闭浏览器，主机和服务持续运行。 | 任务继续执行，重新打开网页能查看进度或结果。 | R18 |
| A19 | 规划期间终止并重启服务进程。 | 未完成任务显示失败或中断并可由用户重试；已完成结果保持可读取。 | R18 |
| A20 | 第一个规划任务尚在运行时再次提交任务。 | 同时运行的规划任务最多一个，其余可查询排队状态，各任务结果保持独立。 | R18 |
| A21 | 导入接近容量目标的中文长文与 PDF，并尝试超过文件数、大小或页数上限。 | 目标容量内可完成导入与检索验证，记录资源与耗时；超出限制时明确提示，失败内容不显示为已完成。 | R07、R19 |
| A22 | 将 `.env` 的模型基址、密钥和模型名从 DeepSeek 验证配置改为另一兼容配置并重启。 | 服务端使用三项新配置，搜索配置独立；验证请求不依赖 DeepSeek 专有参数，配置错误有明确反馈，网页响应不包含完整密钥。 | R17 |
| A23 | 将目的地从西安改为另一个中国大陆城市，例如杭州。 | 资料检索、网络搜索、地点与路线查询使用新目的地，生成对应城市的单城行程。 | R20 |
| A24 | 用户明确将一项活动移到另一日期。 | 按指定跨日移动，核验受影响的两天及全程预算，其他日期保持不变。 | R21 |
| A25 | 使用包含“西安”“碑林”等短词的中文资料，执行导入与查询。 | 资料与查询使用一致分词，检索结果能定位原资料片段；建索引在本机完成。 | R22 |
| A26 | 在无任务运行时停服导出数据卷，再恢复到空安装。 | 偏好、行程、原始资料和全文索引均可读取，重新配置 `.env` 后可继续规划。 | R23 |
| A27 | 未配置 Exa Key，允许匿名，MCP 返回有效搜索来源。 | 经初始化和 tools/list 后调用实际搜索工具，保留来源和 Exa 标识，不调用 Tavily 或 AnySearch。 | R24 |
| A28 | Exa 返回 429 或 MCP 工具错误，Tavily 返回可用结果。 | 识别 HTTP／JSON-RPC／isError 错误，尊重冷却时间并切换 Tavily；成功后停止，来源归属 Tavily。 | R24 |
| A29 | Exa 不可用且未配置 Tavily Key，AnySearch 可用。 | 跳过 Tavily，使用预先确定的 AnySearch 鉴权或匿名模式；记录跳过与失败原因。 | R24 |
| A30 | 三家均失败或没有有效来源。 | 返回汇总原因，保留已有证据及事实待核实状态，无无限重试。 | R11、R12、R24 |
| A31 | Exa 带 Key 请求失败，或提供方处于冷却期。 | 带 Key 失败后转下一家而非同服务匿名重试；后续查询在冷却期跳过限流提供方。 | R24 |
| A32 | 在 Windows x64 按安装说明启动，保存资料与行程后替换容器，并执行备份恢复。 | 本机浏览器可访问，端口绑定回环地址，替换容器后数据保留，空卷恢复后可读取原资料和行程。 | R16、R23 |
| A33 | 分别提交 3 天、7 天以及超出范围或起止日期颠倒的行程。 | 合法输入覆盖准确的起止日期与天数；无效日期明确提示修正。 | R05、R14、R20 |
| A34 | 模型返回无效 JSON、截断内容、空内容或不存在的来源 ID。 | 校验拒绝无效结果，有限修复后仍失败则给出具体原因；无依据的内容不变成已核实事实。 | R11、R13 |
| A35 | 编辑基于旧行程版本，或重新核验过程中发生错误。 | 旧版本写入返回冲突；未成功保存的新结果不覆盖当前可读草案，其他日期保持原值。 | R21 |
| A36 | 首次启动时缺少模型或地图配置，之后补齐并重启。 | 配置检查明确指出缺口，历史数据仍可读取；补齐后可提交规划，页面和日志不显示完整密钥。 | R16、R17 |
| A37 | 活动结束时间晚于停止检票/营业结束，或已知预约与相邻交通冲突。 | 按日期和时区检查内部活动区间，指出具体冲突；无法核实的时间仍为未知。 | R12、R14 |

## 评测记录

| 维度 | 记录方式 |
| --- | --- |
| 硬约束 | 分别记录已满足、已违反和待确认的条件；逐项说明原因。 |
| 事实依据 | 检查时效事实是否关联来源和查询时间，并抽查页面是否支持对应事实。 |
| 时间与路线 | 检查闭馆、营业时段、交通耗时及相邻活动冲突。 |
| 个性化 | 对照当前要求、长期偏好和检索资料，检查优先级是否正确。 |
| 编辑体验 | 记录用户调整次数、调整原因，以及修改后出现或解决的冲突。 |
| 运行记录 | 耗时、工具调用量与费用用于调试，不设通过阈值。 |

“待确认”单独统计，不计入“已满足”。验收围绕明确约束、事实来源和实际修改体验进行。

发布首版前，编号案例按对应的自动或人工方式完成，已知硬约束冲突与未知状态必须准确呈现；没有未处理的数据丢失、错误跨日修改或密钥暴露问题。个人试用记录用户能否完成规划与编辑，以及是否愿意采用；不设置耗时和 API 费用门槛。

## 目标用户试用

首轮由使用者在自己的安装实例中，使用西安旅行条件完成规划、查看事实依据、调整安排并评价采用意愿。需要外部反馈时，可邀请其他人各自安装后试用。

记录用户是否完成任务、在哪一步停顿、修改了哪些内容、是否愿意采用及原因。结合固定案例定位问题属于输入缺口、资料检索、事实来源、行程安排还是编辑交互，并将可复现问题补入案例集。

## Docker 安装验证草案

- 在 Windows（Intel／AMD）上按说明安装 Docker 环境、配置用户自己的 API 密钥并启动应用。
- 写入资料、偏好与行程后重启服务、替换容器，检查数据仍可读取。
- 检查本机浏览器可访问，发布端口仅绑定主机回环地址。
- 按备份说明保存数据，并在另一份空安装中完成恢复；数据库与资料文件应保持一致。
- 检查缺少或错误 API 配置时能给出明确反馈，日志不显示完整密钥。
