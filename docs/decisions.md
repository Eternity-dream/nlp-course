## 方案建议

以下内容来自上一轮推进建议或本轮设计整理，用于评审和后续讨论：

- 先做“西安、三天行程、一份个人资料、一组偏好”的技术验证，再覆盖首版完整范围。
- 以结构化行程承接生成、规则核验与用户编辑；字段草案见[推进计划](plan.md)。
- 首轮由使用者实际试用，需要额外反馈时邀请其他人独立安装体验。
- 开源项目用于参考偏好管理、地点数据、约束核验和评测方式；首版按已选技术栈实现，具体代码复用时检查版本、许可证和接口依赖。

当前产品范围与实施状态见[产品需求](requirements.md#规划状态)。

## 技术选型访谈

技术栈讨论从 Q28 开始，问题、推荐起点和依赖关系记录在[技术栈选型](tech-stack.md)。

| 问题或补充 | 当前结论 |
| --- | --- |
| 简化原则 | 用户明确要求处理尽量简单，资料处理、安装和维护以减少组件、配置与操作步骤为优先。 |
| Q32：使用规模 | 每份安装供单人使用；任务并发与资料容量已分别由 Q39、Q40 细化。 |
| 安装方式 | Q37 已确认 Docker Compose 启动单个应用容器，Windows（Intel／AMD）为首个验收平台。 |
| Q33：托管服务 | 原托管优先建议撤回，采用 Q35 的本地持久化及 Q38 的 SQLite 与本地资料目录。 |
| Q28：语言 | Python 服务端负责规划与资料处理，TypeScript 负责网页。 |
| Q29：网络 | 外部服务优先选择国内直连可用的提供方，允许配置；实际连通性在安装设备核验。 |
| Q30：任务生命周期 | 主机与服务运行时，关闭或刷新网页后规划继续，重新打开可查看结果；进程异常后允许失败并由用户重试。 |
| Q31：PDF | 首版处理可提取文字的 PDF，扫描件识别后续加入。 |
| Q34：安装与访问 | 安装在个人电脑，通过本机浏览器访问。 |
| Q35：数据与 API | 资料、偏好和行程持久化在安装设备；用户自行配置模型、搜索和地图服务密钥，并提供备份说明。 |
| Q36：首个验收平台 | Windows（Intel／AMD）。 |
| Q37：框架与打包 | React + TypeScript + Vite 构建网页，FastAPI 提供 API 和静态网页，Docker Compose 启动单个应用容器；开发时前后端分别调试。 |
| Q38：存储 | SQLite 保存偏好、行程、任务和资料元数据，原始资料保存在持久化目录；知识库使用 Q42 确定的全文索引。 |
| Q39：编排与执行 | Python 显式阶段流程，应用管理状态、超时和有限重试；后台一次执行一个规划任务，其余排队；异常中断后允许用户重试。 |
| Q40：资料容量 | 首轮按 100 份以内资料、单份最多 20 MB、PDF 最多 200 页设计和验证，后续依样本调整。 |
| Q41：服务配置 | `.env` 配置服务提供方、模型和密钥，服务端读取，修改后重启生效；应用提供配置检查结果。 |
| Q42：检索 | 本地提取文字、分段，以中文关键词与 SQLite FTS5 检索相关片段，结合偏好生成行程。 |
| Q43：解析 | PDF 基础文字提取与公开网页正文提取，读取失败时提示用户粘贴文本或上传文件。 |
| Q44：备份 | 应用空闲并停止后手动导出完整数据卷，按说明恢复；`.env` 单独保管。 |
| 模型选择补充 | 用户指定 DeepSeek 用于验证；实际使用由安装者填写 `base_url + api_key + model`，首版按 OpenAI 兼容聊天接口实现。 |
| 搜索调研补充 | 用户要求比较 Tavily、Exa、AnySearch、TinyFish 和 Keenable 的免费额度与付费 Key 接入，搜索服务与模型独立配置。 |
| 搜索回退补充 | 用户选择对 Exa、Tavily、AnySearch 做 fallback；默认依该顺序尝试，Exa 无 Key 时使用官方支持的匿名 MCP。 |

单人使用收窄了 Q18 的资料隔离实现：按独立安装实例维护资料、偏好与行程。固定案例和实际试用继续保留，试用以个人安装体验为主。设计原因见[单人安装决策](adr/0002-single-user-installation.md)。
