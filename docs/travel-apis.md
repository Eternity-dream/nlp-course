# 旅行数据与 API 方案

核对日期：2026-11-14 至 2026-11-15。产品每次规划一个中国大陆城市，西安用于验证。首版的数据需求为真实地点、当地交通和可核对的营业、票价、预约信息；天气作为可选增强。

## 接入优先级

| 能力 | 建议来源 | 首版用途 | 配置与成本 |
| --- | --- | --- | --- |
| 地点、餐饮、行政区划与地址解析 | 高德 Web 服务 API | 确认地点 ID、地址、坐标、城市；查周边餐饮。 | 一个高德 Web 服务 Key，个人开发者需完成认证。 |
| 步行、公交、驾车路线 | 同一高德 Key | 估算相邻活动之间的距离和耗时，核验日程是否可行。 | 与地点服务同账户，额度按不同服务组计。 |
| 营业时间、票价、预约规则 | 搜索 API + 景区／场馆官网 | 读取原文，保存 URL、查询时间和适用日期。 | 共用搜索配置；具体场馆信息以官方当前页面或公告为依据。 |
| 短期天气 | 高德天气 API，可选 | 复用现有 Key，提供当天加未来三天的天气。 | 无需增加提供方账号，受天气服务额度约束。 |
| 7–10 天天气及预警 | 和风天气，可选 | 在行程日期落入预报范围时辅助室内外安排。 | 增加 API Host 与 Key；天气及基础服务分组每月前 50,000 次免费。 |
| 节假日与调休 | 年度官方公告整理为本地数据 | 判断工作日、周末及法定节假日，配合场馆开放规则。 | 首版可本地维护，无需新增付费 API。 |

首版最小组合为可配置模型、Exa → Tavily → AnySearch 搜索回退链和高德地点与路线。天气保留为可选增强；需要时先复用高德短期预报，完整 7 天预报可加和风。航班、住宿与预订保持已有产品范围，以用户提供的条件参与行程。

## 高德：地点与路线

地点搜索 2.0 使用 `GET /v5/place/text`，以用户选定的城市设置 `region` 并使用 `city_limit=true`；输出地点 ID、地址、坐标与城市编码。`show_fields=business` 可请求营业时间和人均消费等字段，缺失字段保留未知状态。见[POI 搜索](https://lbs.amap.com/api/webservice/guide/api-advanced/newpoisearch)。

路线使用步行、公交或驾车相应端点，按接口请求 `show_fields=cost` 取得耗时；保存其为查询时的路线估算。城市编码从服务返回值或行政区划查询获取，所有查询随用户目的地变化。见[路径规划 2.0](https://lbs.amap.com/api/webservice/guide/api/newroute)与[编码说明](https://developer.amap.com/api/webservice/download)。

根据当前[基础服务计费页](https://lbs.amap.com/pages/base_service_price)，个人认证开发者的月免费配额如下。额度按服务分组列出，不能当作每个组内接口各有一份：

| 分组 | 个人认证月配额 | 文档所列 QPS | 超额标价 |
| --- | --- | --- | --- |
| 基础 LBS：路线、地址解析、行政区划等 | 150,000 次 | 3 | 第一档 30 元／万次，之后依月调用量阶梯计价。 |
| 基础搜索：关键词、周边、ID 查询等 | 5,000 次 | 3 | 30 元／万次。 |
| 天气查询 | 5,000 次 | 3 | 30 元／万次。 |

月配额超出后依次消耗流量包与账户余额；该页写明每月 1 日结算上月费用。旧 FAQ 中仍可见“日配额”，本方案采用当前计费页的月配额口径，实际接口权限与分组计量由控制台验证。公开计费页不能替代目标端点的账号开通结果。

## 天气与日期

高德 `GET /v3/weather/weatherInfo` 通过 `extensions=all` 返回当天、第二天、第三天、第四天的预报，因此不能覆盖任意日期的完整 7 天行程。见[天气接口](https://lbs.amap.com/api/webservice/guide/api-advanced/weatherinfo)。

和风当前[每日天气接口](https://dev.qweather.com/docs/api/weather/weather-daily-forecast/)为 `GET /weather/v1/daily/{latitude}/{longitude}`，默认 7 天，可请求 1–10 天；使用用户专属 API Host，鉴权可以采用 `X-QW-Api-Key`，也支持 JWT。参见[鉴权](https://dev.qweather.com/docs/configuration/authentication/)。

和风[按量计费页](https://dev.qweather.com/docs/finance/pricing/)将天气预报、预警、GeoAPI 等归为“天气和基础服务”：每自然月前 50,000 次合计免费，之后 950,000 次为 0.0007 元／次，再按阶梯降低。免费额度按分组共享，计费以小时累计、自然月结算。

天气只在返回预报覆盖的日期上参与规划；旅行日期超出范围时显示尚无对应预报。按响应保留发布时间、时区和来源署名，避免将当天天气套用到未来行程。地图坐标交给天气服务前需按双方文档统一坐标系和经纬度顺序。

## 场馆信息：来源比接口数量更关键

[陕西历史博物馆当前导览](https://www.sxhm.com/guide.html)同时区分本馆和秦汉馆，并提供当前预约与检票规则；[2023 年的预约教程](https://www.sxhm.com/info/announcement/detail/10394.html)仍可被检索到，放票规则与当前导览不同。这适合做“同一官方站点的新旧信息冲突”验收案例：先确认场馆、发布日期和适用条件，再决定引用哪一条，无法消解的冲突保留待核实。

[秦始皇帝陵博物院购票须知](https://www.bmy.com.cn/jingtai/bmyweb/ticketing.html)提供淡旺季停止检票时间、成人与优惠票及官方购票渠道。首版可抓取这些公开说明并给出预约入口；本次文档核对未找到这两家场馆可供个人开发者直接申请 Key 的统一票务 API，因此不把实时余票作为已具备的数据能力。

地点 API 的人均消费用于估算，餐馆宣传、评分和菜单不能自动当作当前总价；真实票价与适用人群需关联来源，费用仍按全体同行者、全程门票餐饮与当地交通汇总。

## 原型验证

先完成地点身份、路线耗时和场馆规则三个链路，使用西安和一个其他城市检查目的地传递。记录服务权限、响应字段、来源日期和失败原因。天气能力在接入时按所选预报服务单独验收；本轮未执行个人账号 API 调用或国内网络测试。
