# 动态旅行规划

规划器根据当前用户意图、已取得地点、事实依据、草案和审核反馈，由 LLM 选择下一步动作。前端继续通过原有任务接口提交、补充、重试与查看结果。

## 动作与反馈

| 动作 | 结果 |
| --- | --- |
| 整理意图 | 从用户原文与问答整理明确限制、偏好、假设、待办及每日区域和主题。自然语言时间附原文引用，计算核验采用这些时间及用户结构化输入。 |
| 查询地点 | 模型根据内容、天数和区域缺口指定查询，地图返回带类别的真实地点。模型选择游览与餐饮候选，后续审核检查附属设施和活动类别。 |
| 查询事实 | 模型选择地点与公开事实主题，搜索、正文提取及引用校验产生事实记录；每个地点都有独立查询机会。 |
| 检索个人资料 | 按当前缺口检索当前安装的资料，每次模型请求重新读取仍存在的片段。 |
| 查询路线 | 比较已取得地点之间的出行方式与耗时，任务内复用相同路线结果。 |
| 生成或修改草案 | 使用模型选定的真实地点与已有证据，参考完整上一版草案和审核反馈。 |
| 补充问题 | 必要缺口或明确冲突交给用户，回答通过弹窗保存到原行程要求，原任务继续。 |
| 提交行程 | 已存在草案时完成路线、规则与模型审核，并保存行程及核验记录。 |

每次草案生成后查询相邻路线，计算活动时间、抵离时间、费用和预算。独立的模型审核检查重复游览、景区入口与别名、餐饮地点适合性、旅行节奏及用户意图。模型收到具体活动引用、问题和建议后，可以补查地点或事实、重新组织每天安排，再修改草案。已知冲突且仍有修改预算时，直接提交会返回修复反馈。

规则负责可以计算和核实的边界：对象引用存在、日期有效、金额口径一致、原文引用存在以及时间和费用计算。模型负责语义理解、查询策略、候选选择和旅行质量判断；模型审核也可能保留待确认项。

## 状态与运行边界

SQLite 版本 5 增加 `planning_checkpoints`，按任务保存意图、公开查询结果、草案、审核及动作记录。每个工具结果和每轮动作后保存。进程中断仍按既有规则显示为中断；用户重试时读取原任务工作状态并获得新一轮运行预算。补充或修改要求后重新整理意图与草案，公开查询结果可复用。

单轮最多 36 次决策、3 次草案生成尝试、80 次地点/事实主题/路线工具动作，地点存储上限 160。上限用于结束无进展或反复查询；不是要求模型填满的配额。供应商内部的搜索回退与有限重试沿用原有边界。

达到上限时，有草案则完成核验并保存具体未解决项；没有草案则返回可重试失败，保留工作状态。提交前仍检查行程要求版本，避免将旧条件生成的结果覆盖当前要求。数据库备份和恢复包含检查点。

编辑继续遵守指定日期与活动身份约束。模型决定受影响日期的公开事实查询，并在规则重排后审核整个行程中与本次编辑有关的质量问题；其他日期保持原值。

## 网页呈现

任务执行时显示当前阶段与“预计”百分比，依据已完成阶段估算，补查和修复期间不回退；任务成功保存后为 100%。它不是完成时间承诺。

完成后默认展示按天行程，行程信息、费用及核验详情折叠。已知执行冲突在对应活动旁简短标注；操作失败保留错误和重试入口。模型动作记录保存在结果的 `planning_context` 中供验收分析，不展示在普通用户流程里。

## 验证

2026-11-18 起，事实提取分别保存地点身份、事实数值和适用规则的原文引用。独立模型审核检查地点/门店/馆区对应、解释是否忠于正文，以及发布者是否为官方来源；程序检查引用存在、数值一致，并按确切日期、日期范围、每周或跨年季节规则计算适用性。节假日例外、第三方来源和未完成审核保留估算或未知状态，过期或不适用规则不记为核实。

预约要求作为独立事实保存，明确需要预约而用户没有对应预约记录时保留待确认项。不同票种与适用人群分别记录，避免将联票与普通门票误判为同一价格冲突。

每项活动可包含简短介绍，介绍地点特色或可体验内容。餐饮默认采用自由用餐时段，地点 ID 仅作区域交通锚点；页面显示午餐/晚餐与约略时段，不展示具体店名和地址。自由用餐不套用锚点的景点营业时间，也不计入该景点门票。编辑同一地点时保留介绍，换地点后清除不再适用的介绍。

自动回归覆盖审核驱动补查与重新生成、未知引用拒绝、上限结果保留、检查点重试、自然语言时间原文引用、首尾非完整日和编辑范围。浏览器使用固定服务响应验证生成、补充、局部编辑、版本、响应式和无障碍。

西安五日真实 HTTP 验收使用两名成人、全程 3500 元的条件，默认日期为 2026-12-05 至 2026-12-09。首日 10:00 到西安北站，末日 18:00 由同站离开，住宿自理。先导入参观笔记，再以 `reference_ids` 关联到本次行程。

```sh
uv run python scripts/accept_agent_live.py --output-dir backups/acceptance/xian-five-days/planning
```

输出目录须为新目录。脚本在其中启动独立实例，外部请求继承当前代理，本机 HTTP 直连，供应商超时为 120 秒。验收从配置状态接口核对 Exa 匿名 MCP、DeepSeek 独立密钥 REST、Tavily 禁用和 AnySearch 匿名 REST 的顺序，并分别触发模型、地图和搜索连通性检查。日期可通过 `--start-date` 更改。

脚本记录五日日程、介绍、自由用餐、重复地点、事实状态、搜索尝试和全部规则问题。局部编辑将第二天的一项活动缩短 15 分钟，逐项复算费用，比较其余日期的活动、路线、证据及历史版本。停服后执行校验、备份和异目录恢复，再校验并通过 HTTP 读回两个版本。

长期偏好可用同一独立实例中的两次三日规划做对照。A 组仅提供抵离与住宿条件，B 组增加明确的夜游要求。脚本保留模型意图、实际开始时间、晚间地点、步行耗时和介绍正文，并检查偏好版本冲突、主动更新及重启后读回。
